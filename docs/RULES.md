# 站点硬规则 v1

> 这份文件是站点的"宪法"。改规则 = 改这里 + 改对应测试；代码与文档不一致时以**测试**为准。

---

## A. 托管与访问

| # | 规则 | 落地位置 |
|---|---|---|
| A-1 | 仅静态文件，零后端、零数据库、零构建 | 全部文件 |
| A-2 | **内部链接一律相对路径**，禁止 `/xxx` 绝对路径（子路径部署会 404） | `tools/check.mjs` 自动检查 |
| A-3 | 发布：`main` 分支 push → Actions → Pages | `.github/workflows/pages.yml` |
| A-4 | **不许出现任何外部域名**（CDN / 字体 / 统计 / 广告）。离线可用是硬要求 | `tools/check.mjs` 自动检查 |
| A-5 | 静态资源带版本查询串 `?v=N`，改文件就加一 | `talos.html` 引用处 |
| A-6 | 根目录放 `.nojekyll`，避免 GitHub 的 Jekyll 过滤掉下划线开头的路径 | `.nojekyll` |

## B. 内容与合规

| # | 规则 |
|---|---|
| B-1 | 定位为"非官方玩家自建"。页脚必须含"非官方 / 数值以游戏内为准"字样 |
| B-2 | 不提供虚拟物品交易、代练、第三方修改工具的任何入口或链接 |
| B-3 | 引用他人攻略必须标来源与整理日期 |
| B-4 | **所有游戏数值只能写在 `assets/js/data.js`**；HTML / engine / ui 里不许出现硬编码数值 |
| B-5 | 改数据必须同步提升 `DATA_VERSION`；`localStorage` 存档按版本隔离，旧档自动失效而非崩溃 |
| B-6 | 不收集任何用户数据，不含第三方统计。用户进度只存本地 `localStorage`，并提供导出/导入 JSON |

## C. 代码与规则

| # | 规则 |
|---|---|
| C-1 | 原生 HTML / CSS / ES Module，不引入框架、不引入构建步骤 |
| C-2 | 三层分离：`data.js`（数据）/ `engine.js`（纯函数）/ `ui.js`（DOM） |
| C-3 | **`engine.js` 必须是纯函数**：无 DOM、无 localStorage、无 `Date.now()`、不自己造随机数。随机由调用方传入 |
| C-4 | 每条规则都要有对应测试（`test/engine.test.mjs`，命名 `T-<规则号>`），`node --test` 必须全绿 |
| C-5 | 前瞻性：CI 先跑测试与自检，再发布。任何一项失败都不部署 |

### C-3 具体口径（这些是被"实测/口径化"过的，不要凭直觉改）

1. **吃成立条件**：默认「同阶 + 克制」；跨阶必须满足克制，且需要对应刑具。
2. **升阶公式**：`基线 = 发起方阶 + 1`；象脚重锤向上跨阶为 `目标阶 + 2`（覆盖基线）；铁冠 / 鼠头串 / 口枷是**额外 +N**，取最大值。
3. **铁冠的"同阶任意吃"全局生效**：持铁冠时任何同阶组合都成立（不区分是谁拿着铁冠）。
4. **口枷按"全场含自己与目标"计人数**：`onBoardCount() <= 3` 才额外升阶 —— 这是原版文案与实现不一致的地方，我们选择显式写进规则并测试锁定。
5. **绮彩（6 阶）不入沙盘**：升到 6 即移出、彩池 +1、原房重新上锁。
6. **彩池上限 10**：满了以后**拒绝**任何"出彩"操作，且建议区不许再冒出彩。
7. **开吃日三档**：早吃件 → 第 1 天；晚吃件 → 第 15 天；其余 → 第 8 天。**同时持有时取晚的那天。**
8. **天数唯一来源**：`remaining = lastDay - days`；只有"移动"会推进 `days`，吃/换不推进。
9. **候选房**：只有用户填进"今日选项"、且**还没开过**的房间才允许出现在"开房"建议里；被吃空的格子立刻从选项里移除。

## D. 建议优先级（`data.js` 的 `RULES.prio`）

| prio | 建议 | 备注 |
|---|---|---|
| 0 | 彩池已满，停手 | 硬拦截；同屏不会再出现"出彩" |

| 1 | 【出彩】 | 当前房发起的同阶克制吃 |
| 2 | 【升红】 | 升到至臻，下一口就能出彩 |
| 2.4 / 2.6 | 跨阶出彩 / 跨阶 | |

| 3.2 | 开吃日还没到，先别吃 | |
| 3 | 紫阶吃紫阶 | |

## E. 无障碍与移动端

| # | 规则 |
|---|---|
| E-1 | 每个交互件可按键盘到达；纯 emoji 按钮必须有 `aria-label` 或可读文本 |
| E-2 | 动态建议区用 `aria-live="polite"` 播报，且播报的"首要建议"必须与视觉第一条一致 |
| E-3 | 房间格子的 `aria-label` 必须包含：房号、是否审讯室、是否当前所在、是否今日候选、囚犯信息、事件标记 |
| E-4 | 断点 700px：棋盘从环形切为顺序网格 |
| E-5 | 支持 `prefers-color-scheme` + 手动三态（跟随系统 / 浅色 / 深色） |

## F. 已知不做的（scope cut）

- 不做账号、不做云存档、不做多人协作。
- 不做游戏数值的自动抓取（手动维护 `data.js`）。
- 不做"自动最优解求解"（本工具是**规则查表 + 启发式评分**，不是博弈求解器）。
